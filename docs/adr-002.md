# ADR-002 — Modelo de datos y contratos

- Estado: Aceptado
- Versión: 1.0
- Depende de: ADR-001

## 1. Entidades

### Profile
```ts
{ name, role: Localized, summary: Localized, email, phone, linkedin, github, available: Localized }
```

### Experience
```ts
{ id, company, siteUrl?, position: Localized, period, location: Localized, bullets: Localized[], techIds: string[] }
```
Dato real v1: DimeloIA 2026-Actualidad, 6 bullets (FastAPI/SQLAlchemy, React/TS, móvil, PostgreSQL, IA, Redis/Docker/Git).

### Project (ver `project.types.ts`)
Campos: id, slug, name, tagline, description, problem, role, stack: TechnologyReference[], featured, siteUrl?, repoUrl?.
Slugs fijos: `dimeloia`, `jumpproxy-engine`, `captcha-bypass`, `jetx-collector`.

### Technology
```ts
{ id, name, category: backend|frontend|database|devops|mobile|ai|testing|cms, context: Localized }
```
Organizado por especialidad, sin porcentajes. Contexto = dónde se usó.

### Education / Languages
```ts
{ id, title, institution, year: Localized, status }
{ code: 'es'|'en', level: Localized }
```
Bachiller Castilla 2020, Ingeniería Sistemas Central 2022-Actual, EN básico / ES nativo.

### Achievement
```ts
{ id, title: Localized, detail: Localized, evidence?: 'repo'|'site'|'cv', refIds?: string[] }
```
Sin métricas inventadas. Solo verificables.

### Contact
```ts
{ email, linkedin, github, phone? } // mailto: real, sin formulario falso
```

## 2. Relaciones
- Experience.techIds -> Technology.id
- Project.stack[].id -> Technology.id (referencia, no duplicar)
- Achievement.refIds -> Project.id | Experience.id
- Identity es fuente para header/footer/metadata.

## 3. Validación
- Zod solo donde aporte valor (contenido externo, formularios futuros). TS no sustituye runtime.
- Reglas: email formato, URLs https/mailto, slugs kebab-case únicos, locale es|en, arrays no vacíos en bullets/stack.

## 4. Repositorios
Interfaces async (`findAll(locale)`, `findBySlug`) aunque hoy lean archivos locales.
Permite migrar a CMS/API sin romper dominios. Presentation nunca importa `infrastructure/data` directo.

## 5. DTOs
Los mismos tipos son DTOs en v1 (lectura). Si aparece escritura, se crean Input/Output separados.
